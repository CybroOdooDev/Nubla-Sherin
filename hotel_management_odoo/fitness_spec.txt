1. Executive Summary
This document defines the complete product specification for a world-class Fitness
Center Management Platform built on Odoo 19. Unlike the previous sprint-focused plan,
this specification prioritizes building the best possible product by drawing inspiration from
seven industry leaders.
Our platform uniquely combines gym operations management (like
Mindbody/GymMaster) with personal fitness tracking (like Fitbit), social engagement (like
Strava), AI-powered coaching (like Freeletics), guided wellness (like cult.fit Mind.fit +
Down Dog), nutrition management (like cult.fit Eat.fit), and premium class experiences
(like Peloton) into a single integrated Odoo module.

1.1 Product Vision
Build a cult.fit-inspired fitness ecosystem within Odoo 19 that serves as the single
platform for gym owners, trainers, and members, covering the complete fitness journey
from signup to transformation.

1.2 Key Differentiators
●​ All-in-One Ecosystem: Six product verticals (FIT, WORKOUT, EAT, MIND, SOCIAL, CARE) in
     one Odoo module, unlike competitors that only cover 1-2 areas.
●​   Frontend-First Design: OWL 3.x components drive the experience, with 8 custom widgets
     (dashboard, workout timer, activity feed, check-in kiosk, leaderboard, meal tracker, meditation
     player, body scanner).
●​   AI Coach: Rule-based recommendation engine (ML-ready) that personalizes workouts,
     meals, and wellness sessions based on member profile, history, and goals. Inspired by
     Freeletics AI Coach.
●​   Gym + Personal Fitness: Manages gym operations (equipment, classes, trainers, billing) AND
     personal fitness tracking (workouts, nutrition, body metrics, sleep), unlike any single
     competitor.
●​   Social-First: Strava-inspired social network with friends, activity feed, kudos, leaderboards,
     challenges, achievements, and clubs, making fitness a community experience.
●​   cult.fit Wellness: Mind.fit-inspired meditation, sleep tracking, stress management, and Down
     Dog-style AI-generated yoga sessions with customizable pace/focus/duration.

FIT (Gym + Classes)

13. AI Recommendation Engine
Inspired by Freeletics AI Coach (trained on 56M+ users) and Fitbit's Gemini-powered
health coach, our AI engine provides personalized recommendations across workouts,
nutrition, and wellness. Phase 1 uses rule-based logic; Phase 2 upgrades to ML models.




13.1 AI Model
fitness.ai.recommendation: member_id, type
(workout/meal/class/wellness/deload/goal_adjust), content (Text), reasoning (Text),
confidence_score (Float), status (suggested/accepted/dismissed), generated_date,
applied_date, source (rule_based/ml_model)

13.2 Rule-Based Logic (Phase 1)
●​ Workout Selection: Match exercises to member goal + available equipment + fitness level.
    Increase difficulty every 2 weeks if completion rate > 80%.
●​ Deload Detection: If 3+ consecutive sessions show declining performance (fewer reps or
    lower weight), suggest a deload week with 50% volume.
●​ Meal Suggestions: Based on daily calorie target minus consumed, suggest meals from
   database that fit remaining macro budget.
●​ Class Recommendations: Based on member preferences, past attendance, and schedule
   gaps, suggest upcoming classes with available spots.
●​ Recovery Alerts: If member worked same muscle group 2 days in a row, suggest rest or
   different focus area.
●​ Streak Motivation: If member is 1 day from breaking their longest streak, send motivational
   notification.

17. Odoo 19 Technical Requirements
Mandatory development rules for Odoo 19:
●​   Python 3.12+ with type hints MANDATORY on all method signatures.
●​   SQL() builder for ALL raw SQL. No string concatenation or f-strings in queries.
●​   Views: <list> not <tree>. invisible/readonly use Python expressions directly (no attrs dict).
●​   Security groups: Use privilege_id NOT category_id for res.groups.
●​   Search views: group must use name=group_by only. Never expand or string attributes.
●​   Cron: No numbercall/doall attributes (removed). Use interval_number + interval_type.
●​   HTTP routes: type="jsonrpc" on all @http.route. type="json" REMOVED.
●​   res.partner: mobile field REMOVED. Store mobile directly on model.
●​   OWL 3.x required. Register components as ir.actions.client. Use type="action" for stat
     buttons.
●​   Manifest order: security XML -> ir.model.access.csv -> views -> menus -> data.
●​   Never check_company=True on res.company fields.
●​   Sale list views: Never ref sale.view_quotation_list (removed in v19).
●​   Module delivery: Always as single ZIP file in addons/ directory structure.

A key differentiator of this module is the complete website and portal layer that allows
members, trainers, and prospects to interact with the fitness center entirely through the
Odoo website. This follows the frontend-first architecture: every backend model is
designed to power a customer-facing experience. The portal extends Odoo's native
portal framework (portal.mixin) while the public website uses website.published.mixin
and QWeb templates for SEO-friendly, mobile-responsive pages.

18.1 Architecture Overview
The website/portal layer consists of three tiers:
1. Public Website Pages — No login required. Visitors can browse membership plans,
class schedules, trainer profiles, center locations, workout library, and recipes. Designed
for SEO with website.seo.metadata mixin. 15 public pages across all phases.
2. Member Portal — Authenticated pages under /my/fitness/. Members manage
subscriptions, book classes, log workouts, track nutrition, participate in challenges, earn
rewards, and view progress analytics. 19 portal pages.
3. Trainer Portal — Authenticated pages under /my/trainer/. Trainers manage their class
rosters, mark attendance, view client progress, and build custom workout templates. 4
trainer-specific pages.

18.5 Technical Implementation
18.5.1 Module Dependencies
The website/portal layer requires the following Odoo depends in __manifest__.py:
website, portal, payment, website_blog (optional). These are added to the existing
fitness_center module depends list. The assets key in the manifest registers all frontend
SCSS, JavaScript, and OWL components under web.assets_frontend.

18.5.2 Mixin Integration
Core models gain website and portal capabilities through mixin inheritance:
●​ portal.mixin added to: fitness.member, fitness.subscription, fitness.class.booking,
   fitness.workout.session, fitness.pt.session, fitness.payment — provides
   access_token and access_url
●​ website.published.mixin added to: fitness.membership.plan, fitness.class.template,
   fitness.trainer, fitness.workout.template, fitness.recipe, fitness.challenge — provides
   website_published and is_published toggle
●​ website.seo.metadata added to all website.published models — provides
   website_meta_title, website_meta_description, og:image for SEO optimization

18.5.3 Controller Architecture
Three controller classes handle all routes:
●​ FitnessWebsiteController(http.Controller) — 16 public routes for the website
   pages. Uses auth="public", website=True. All queries use sudo() for public access.
   Includes AJAX endpoints (type="jsonrpc") for dynamic filtering on class schedule and
   food search.
●​ FitnessMemberPortal(CustomerPortal) — 24 routes for member self-service.
   Extends Odoo's CustomerPortal with _prepare_home_portal_values for counters.
   Uses auth="user". Includes 4 AJAX endpoints for booking, meal logging, community
   posts, and reward redemption.
●​ FitnessTrainerPortal(CustomerPortal) — 5 routes for trainer portal. Verifies trainer
   role via record rules. Includes AJAX endpoint for attendance marking.

18.5.4 QWeb Templates
The module includes 40 QWeb templates organized as: 11 public website page
templates (inheriting website.layout), 20 portal templates (inheriting portal.portal_layout),
5 trainer portal templates, and 4 website builder snippets (membership pricing table,
class carousel, trainer spotlight, testimonial carousel). All templates use Bootstrap 5
classes for responsive design and follow Odoo's website builder compatibility patterns.
18.5.5 Portal Security
Portal access is secured through ir.rule record rules for base.group_portal:
●​ Members can only read their own records: subscriptions, bookings, workouts,
   nutrition, challenges, rewards, invoices (domain: partner_id = user.partner_id.id)
●​ Trainers can read their assigned classes, clients, and PT sessions (domain:
   trainer_id.partner_id = user.partner_id.id)
●​ Write access is granted only for specific actions: booking creation, meal logging,
   profile editing, community posting, and workout session recording

18.5.6 Frontend Assets
Custom frontend assets are registered in the manifest under web.assets_frontend:
●​ SCSS — Custom styles for fitness pages, dark/light theme support, responsive
   breakpoints, animation classes for progress bars and charts
●​ JavaScript — Public widgets for dynamic filtering (class schedule, food search),
   AJAX form submissions, interactive charts (Chart.js), barcode scanner integration,
   and the OWL 3.x components that render within portal pages
●​ PWA (Phase 4) — Progressive Web App configuration with service worker for offline
   support, manifest.json for home screen installation, and push notification subscription

18.6 Key User Journeys (Website → Portal)
Journey 1: New Member Signup
Visitor lands on homepage (/) → browses membership plans (/membership/plans) →
views plan detail → clicks "Join Now" → fills multi-step signup form
(/membership/signup/<id>) with personal info, health questionnaire, applies promo code
→ completes payment → auto-creates fitness.member + fitness.subscription + portal
user → redirected to member dashboard (/my/fitness) → sees first-time onboarding
tutorial.
Journey 2: Class Booking
Member logs into portal → views class schedule (/classes or /my/fitness/bookings) →
filters by yoga category → finds available slot → clicks "Book" → system creates
fitness.class.booking → confirmation email sent → class appears in "My Bookings" with
calendar export link → day of class: member checks in via kiosk → trainer marks
attendance.
Journey 3: Workout + Nutrition Tracking
Member visits /my/fitness/workouts → browses workout library → selects "Upper Body
Strength" → clicks "Start Workout" → redirected to OWL WorkoutPlayer component →
completes workout with set/rep logging → session saved → navigates to
/my/fitness/nutrition → logs post-workout meal with barcode scan → calorie ring updates
→ views progress at /my/fitness/progress.
Journey 4: Trainer Workflow
Trainer logs into /my/trainer → sees today's 3 group classes and 2 PT sessions → clicks
into 9am Yoga class → views roster of 18 enrolled members → marks attendance as
members check in → adds session notes → navigates to PT client → reviews client's
workout history and body measurements → creates custom workout template using
drag-drop builder → assigns to client's plan.
