NHS Trust | Epic Integration

A complete Odoo module for NHS Trusts — sync patients, clinical notes, appointments, allergies and conditions directly from your Epic EHR system using the FHIR R4 API.


FHIR R4 Epic EHR NHS-Ready Odoo 19

Overview

This module bridges your NHS Trust's operational workflows in Odoo with your Epic Electronic Health Record system. Using Epic's SMART on FHIR Backend Services (OAuth2 + JWT), it securely authenticates as a backend system and synchronises clinical data in real time — no patient login required.

Built with NHS-specific data requirements in mind: NHS numbers, ODS organisation codes, CQC registration, ward management, GMC/NMC staff identifiers, and NHS ethnic group classifications are all supported out of the box.

Key Features

🏥

Ward Management

Manage NHS wards and departments — General, ICU, HDU, Maternity, A&E, Oncology and more. Track bed capacity and current patient census per ward.

🧑‍⚕️

Patient Records

Full NHS patient profiles with NHS Number, ward assignment, GP details, blood type, next of kin, and NHS ethnic group codes (16+1 classification).

📅

Appointment Sync

Pull appointment schedules from Epic with status tracking (booked, arrived, fulfilled, cancelled). Filter by date, patient, or status.

📋

Clinical Notes

Sync DocumentReference clinical notes from Epic including full HTML and plain-text content. Supports multiple note types via LOINC codes.

⚠️

Allergies & Intolerances

Bi-directional allergy management — pull from Epic and push new records back. Includes criticality, reaction severity, substance codes (SNOMED/RxNorm).

🩺

Conditions / Diagnoses

Sync problem lists and encounter diagnoses from Epic. Push new conditions with ICD-10/SNOMED coding. Tracks clinical and verification status.

👨‍⚕️

Clinical Staff

Practitioner records with GMC number, NMC Pin, specialty, department and role (Consultant, Registrar, Nurse, GP, Pharmacist, etc.).

🔐

Role-Based Security

Three NHS-specific roles: Trust Administrator, Clinician, and Receptionist — with carefully defined access rights for each clinical data type.

🔗

Secure FHIR Auth

Uses Epic SMART Backend Services with RS384 JWT signing and JWKS public key hosting. Supports both sandbox (Open Epic) and production environments.

Role-Based Access Control

Trust Administrator

  • Epic API configuration
  • Ward creation & management
  • Full CRUD on all data
  • Staff management

Clinician

  • Patient records (create/edit)
  • Clinical notes
  • Allergies & conditions
  • Appointments (view/edit)

Receptionist

  • Patient demographics
  • Appointment booking

  • Ward directory

Epic API Setup

1

Register in Epic App Orchard

Create a Backend Systems application at open.epic.com. Set Application Audience to Backend Systems and Use Case to General.

2

Add Required Incoming APIs

Select all R4 variants of: Patient, Practitioner, PractitionerRole, Appointment, AllergyIntolerance, Condition, DocumentReference (Clinical Notes), and Binary (Clinical Notes).

3

Generate RSA Key Pair

Generate an RS384 key pair. Host the JWKS (public key) at /epic/jwks.json — Odoo serves this automatically from Settings.

4

Configure in Odoo Settings

Go to Settings → NHS Trust | Epic Integration. Enter your Client IDs, token endpoint, FHIR base URL, private key, and JWKS. Click Test Connection to verify.

5

Start Syncing

Use the Sync from Epic buttons on each list view to pull data. Push patient, allergy, and condition records back to Epic using the Push to Epic button on individual records.

Technical Requirements

  • Odoo 19 (Community or Enterprise)
  • Python package: PyJWT — install via pip install PyJWT
  • Epic App Orchard account (open.epic.com for sandbox testing)
  • RS384 RSA key pair (2048-bit minimum)
